# Code Review: Workspace Runtime and Terminal Work

## Summary

I reviewed the files changed since `HEAD~1`. The commit adds a persistent workspace runtime, a browser terminal backed by the sidecar, workspace file APIs, `.env` guardrails, frontend workspace inspector UI, and test coverage.

The review found three areas that should be fixed before shipping broadly. First, the workspace file API trusts the workspace path stored in SQLite. The terminal endpoint repairs and validates that path before use, but the file endpoints do not. Second, the sidecar terminal starts the shell with the whole sidecar environment, which can expose future process secrets to users through `env`. Third, the inspector mounts hidden UI that still opens a terminal socket and starts polling. That can keep containers warm and scan the filesystem even when the user cannot see the panel.

No product code was changed during this review. This Markdown report is the only file created.

## Design Findings

### DESIGN-1: Hidden inspector UI still controls runtime lifecycle

Software-design flagged a boundary problem in `frontend/src/pages/Session.tsx:569-574`, `frontend/src/components/WorkspaceInspector.tsx:257-326`, and `frontend/src/components/WorkspaceInspector.tsx:380-386`.

`Session.tsx` renders the desktop inspector whenever a workspace exists:

```tsx
<WorkspaceInspector
  workspaceId={workspaceId}
  refreshKey={fileRefreshKey}
  className="hidden lg:flex"
  style={{ width: inspectorWidth }}
/>
```

The `hidden lg:flex` class only changes CSS display. React still mounts the component on small screens. Once mounted, `TerminalPane` runs its effect and opens the terminal socket:

```tsx
const socket = new WebSocket(workspaceTerminalUrl(workspaceId));
```

The same component starts a timer that refreshes the file tree and changed-file list every 5 seconds while the document is visible.

This design makes a hidden component own an expensive backend lifecycle. A mobile user who never opens the workspace panel can still start a shell, keep a runtime alive, and trigger repeated backend work. If the mobile overlay is opened, the app can mount a second inspector with another timer.

Move the lifecycle behind an explicit visibility check. One option is to mount `WorkspaceInspector` only for the active layout. Another option is to pass an `active` prop and let the terminal plus polling effects return early when inactive. The terminal should also connect lazily when the terminal pane is actually visible or selected.

### DESIGN-2: Path safety rules are split between routes

Software-design found repeated path-safety knowledge in `backend/src/yinshi/api/workspace_files.py:48-61` and `backend/src/yinshi/api/terminals.py:171-188`.

The terminal endpoint repairs the workspace checkout and checks the workspace path against `tenant.data_dir`:

```python
await ensure_workspace_checkout_for_tenant(db, tenant, workspace_id)
row = _workspace_row(db, workspace_id)
if not is_path_inside(workspace_path, tenant.data_dir):
    await websocket.close(code=_TERMINAL_CLOSE_POLICY)
    return
```

The file API uses a separate helper that reads paths from SQLite and installs guardrails:

```python
workspace_path = str(row["path"])
repo_root_path = str(row["root_path"])
ensure_secret_guardrails(repo_root_path)
return workspace_path, repo_root_path
```

Both features depend on the same invariant: a workspace path used for host file access must belong to the current tenant. Today that invariant lives in one route but not in the other. That is information leakage because callers must remember an implementation detail that should live in one module.

Create one shared helper that loads the workspace, repairs migrated paths, validates tenant containment, installs guardrails, and returns a small typed result. Terminal, stream, and file APIs can all call that helper instead of repeating partial checks.

### DESIGN-3: Container lifecycle sequencing is exposed to routes

Software-design also flagged shallow lifecycle plumbing in `backend/src/yinshi/api/terminals.py:190-230` and `backend/src/yinshi/services/sidecar_runtime.py:231-320`.

The terminal route resolves the runtime, begins activity, proxies traffic, ends activity, and protects the container with a keepalive lease. This sequence matters because it decides whether the container can be replaced or reaped. The route is also doing WebSocket protocol work, so lifecycle policy is mixed with transport code.

A deeper interface would hide the sequence behind an async context manager:

```python
async with workspace_runtime(request, tenant, workspace_id) as runtime:
    await proxy_terminal(websocket, runtime)
```

That structure lets the route describe terminal behavior while the runtime service owns begin, end, and keepalive protection. It also reduces the chance that a future caller forgets cleanup.

## Security Findings

### HIGH: Workspace file APIs can use an unsafe root path

Security-sentinel flagged `backend/src/yinshi/api/workspace_files.py:48-61` and every endpoint in `backend/src/yinshi/api/workspace_files.py:77-163`.

The new file endpoints list, preview, diff, edit, and download workspace files. They all call `_prepare_workspace_files()`, which returns `workspace_path` directly from the database:

```python
workspace_path = str(row["path"])
repo_root_path = str(row["root_path"])
ensure_secret_guardrails(repo_root_path)
return workspace_path, repo_root_path
```

Later calls use that root for host file operations:

```python
nodes = build_file_tree(workspace_path)
return {"path": path, "content": read_text_file(workspace_path, path)}
write_text_file(workspace_path, path, body.content)
return FileResponse(file_path, filename=file_path.name)
```

`validate_visible_relative_path()` keeps the requested file inside `workspace_path`, which is good. The missing check is whether `workspace_path` itself is a trusted tenant path. A stale migration row, corrupted row, or older local import can point outside tenant storage. In that case the relative path check still succeeds, but it succeeds inside the wrong root.

The terminal endpoint already handles this risk by calling `ensure_workspace_checkout_for_tenant()` and then rejecting paths outside `tenant.data_dir`. The file API should use the same rule before touching the filesystem.

Recommended fix:

```python
tenant = require_tenant(request)
await ensure_workspace_checkout_for_tenant(db, tenant, workspace_id)
row = _workspace_row(db, workspace_id, request)
workspace_path = str(row["path"])
repo_root_path = str(row["root_path"])
if not is_path_inside(workspace_path, tenant.data_dir):
    raise HTTPException(status_code=403, detail="Workspace path is outside tenant storage")
if not is_path_inside(repo_root_path, tenant.data_dir):
    raise HTTPException(status_code=403, detail="Repository path is outside tenant storage")
```

Legacy non-tenant mode can keep its existing local-import controls. Hosted tenant mode should fail closed for host paths.

### MEDIUM: Terminal shell inherits the full sidecar environment

Security-sentinel flagged `sidecar/src/sidecar.js:885-898`.

The sidecar starts a PTY shell with this environment:

```js
const terminalEnvironment = {
  ...process.env,
  TERM: "xterm-256color",
  COLORTERM: "truecolor",
  PWD: cwd,
};
```

That means every sidecar process variable is available inside the user shell. A user can run `env` or `printenv` to read those values. Today the container manager sends a small environment, but this code creates a future footgun. If provider tokens, encryption keys, or operational credentials ever reach the sidecar process environment, the terminal will expose them.

Use an allowlist instead:

```js
const terminalEnvironment = {
  HOME: process.env.HOME || "/home/yinshi",
  PATH: process.env.PATH || "/usr/local/bin:/usr/bin:/bin",
  SHELL: shell,
  TERM: "xterm-256color",
  COLORTERM: "truecolor",
  PWD: cwd,
};
```

The terminal remains useful, and control-plane secrets do not become part of the shell contract.

### MEDIUM: `.env` Git guardrails prevent accidents but do not enforce a hard block

Security-sentinel flagged `backend/src/yinshi/services/workspace_files.py:343-384`.

The code adds `.env` patterns to `.git/info/exclude` and appends a `pre-commit` hook that blocks staged `.env` files:

```sh
if git diff --cached --name-only --diff-filter=ACM | grep -E '(^|/)\.env(\..*)?$' >/dev/null; then
  echo 'Yinshi blocks committing .env files. Move secrets out of Git.' >&2
  exit 1
fi
```

This prevents common mistakes such as `git add .` followed by a normal commit. The hosted terminal still gives users direct shell access, so a user or agent can bypass the local hook with `git commit --no-verify`. An existing hook can also exit before the appended Yinshi block runs.

Keep the local guardrails because they reduce accidental leaks. For an enforceable guarantee, add a server-side check such as a pre-receive hook on the managed remote, or add a service-side scan before any managed push. Remote-side enforcement cannot be bypassed with `--no-verify`.

## Performance Findings

### MAJOR: Hidden or duplicate inspectors can start backend work

Performance-oracle flagged `frontend/src/pages/Session.tsx:569-574`, `frontend/src/pages/Session.tsx:578-592`, `frontend/src/components/WorkspaceInspector.tsx:257-326`, and `frontend/src/components/WorkspaceInspector.tsx:380-386`.

Each mounted inspector opens its own terminal socket and owns its own refresh timer. The desktop inspector is mounted whenever a workspace exists. The mobile inspector mounts when the overlay is open. On a hidden desktop inspector, CSS hides the UI but effects still run.

This scales poorly with multiple tabs, mobile layout, and several workspaces. Each extra inspector can keep a container active and add repeated filesystem work. The fix is the same as DESIGN-1: mount only the visible inspector, or pass an explicit `active` flag that disables the terminal effect and refresh timer.

### MAJOR: Five-second polling repeatedly walks the filesystem and runs Git status

Performance-oracle flagged `frontend/src/components/WorkspaceInspector.tsx:362-386`, `backend/src/yinshi/services/workspace_files.py:159-200`, and `backend/src/yinshi/services/workspace_files.py:251-268`.

Every refresh calls both file endpoints:

```tsx
const [treeResponse, changedResponse] = await Promise.all([
  api.get(`/api/workspaces/${workspaceId}/files/tree`),
  api.get(`/api/workspaces/${workspaceId}/files/changed`),
]);
```

The tree endpoint walks up to 5,000 entries. The changed-files endpoint runs:

```python
git status --porcelain=v1 -z --untracked-files=all
```

`--untracked-files=all` can be expensive because Git enumerates every untracked file. In a large repository, generated output directory, or multi-tab session, this becomes steady disk churn.

Reduce the refresh rate and avoid rebuilding the whole tree on every tick. Refresh on focus, save, and agent completion. Poll only the changed-file endpoint if live status is required. Pause polling while the panel is inactive. Consider `--untracked-files=normal` unless the UI must show every nested untracked path.

### MINOR: Diff for untracked files reruns full status

Performance-oracle flagged `backend/src/yinshi/services/workspace_files.py:311-340`.

`diff_file()` calls `changed_files()` to determine whether a file is untracked. For tracked files it then runs `git diff`. When the user opens a diff from the changes list, the frontend already has the change kind, but the backend recomputes full status.

This is not urgent. At larger scale it repeats process work on a review path. A later improvement could add a dedicated untracked-file diff path or accept a client-provided status hint that the server validates cheaply before use.

## Code Quality Findings

### MAJOR: File routes catch broad exceptions without logging unexpected bugs

Python-reviewer flagged `backend/src/yinshi/api/workspace_files.py:82-163`.

Each endpoint catches `Exception` and passes it to `_map_file_error()`:

```python
try:
    nodes = build_file_tree(workspace_path)
except Exception as exc:
    raise _map_file_error(exc) from exc
```

Mapping known domain errors is good. `FileNotFoundError`, `PermissionError`, `ValueError`, and `GitError` become stable HTTP responses. The problem is that unexpected programmer errors also get caught and converted to a generic 500 with no log entry. That makes production bugs harder to trace.

Catch known exceptions first, then log the unexpected path:

```python
except (FileNotFoundError, PermissionError, TypeError, ValueError, GitError) as exc:
    raise _map_file_error(exc) from exc
except Exception as exc:
    logger.exception("Unexpected workspace file error: workspace=%s", workspace_id)
    raise HTTPException(status_code=500, detail="Workspace file operation failed") from exc
```

This keeps client responses stable while preserving operator visibility.

### MAJOR: Backend terminal success path lacks integration coverage

Python-reviewer flagged the test coverage around `backend/src/yinshi/api/terminals.py`.

`sidecar/tests/terminal.test.js` proves the sidecar can start a PTY. The backend tests cover some rejection paths and helper behavior. They do not cover a successful public WebSocket request through authentication, checkout repair, container resolution, sidecar attach, browser input forwarding, and cleanup.

The backend endpoint is the main security boundary for the browser terminal. Add an integration-style test with a mocked container manager and a fake sidecar socket. It should verify valid Origin plus session cookie, checkout repair, rejection for paths outside tenant storage, the outbound `terminal_attach` message, and cleanup through `end_tenant_container_activity()` plus `protect_tenant_container()`.

### MINOR: Tree sorting can touch symlink targets before symlink filtering

Python-reviewer flagged `backend/src/yinshi/services/workspace_files.py:164-185`.

The tree builder sorts children with `item.is_file()`:

```python
for child in sorted(
    directory_path.iterdir(), key=lambda item: (item.is_file(), item.name.lower())
):
```

`Path.is_file()` follows symlinks. The code later uses `lstat()` and skips symlinks, but sorting has already had a chance to touch the target. That can make a symlink to a slow or unavailable target affect tree building.

Classify entries with `lstat()` first, skip symlinks, then sort the safe in-memory records by type and name.

## Simplification Findings

### MINOR: `_prepare_workspace_files()` returns a value callers ignore

Code-simplicity-reviewer flagged `backend/src/yinshi/api/workspace_files.py:48-61`.

The helper returns both paths:

```python
return workspace_path, repo_root_path
```

Every caller discards the repo path:

```python
workspace_path, _ = _prepare_workspace_files(db, workspace_id, request)
```

The repo path only matters inside the helper because it is used for `ensure_secret_guardrails()`. Returning it makes call sites carry unused detail. After the security fix, either return only `workspace_path` or return a named object from the shared path-preparation helper.

### MINOR: `_auth_disabled()` only delegates to `auth_disabled()`

Code-simplicity-reviewer flagged `backend/src/yinshi/auth.py:223-233`.

The module has a public helper and a private wrapper:

```python
def auth_disabled() -> bool:
    settings = get_settings()
    return settings.disable_auth or (
        not settings.google_client_id and not settings.github_client_id
    )


def _auth_disabled() -> bool:
    return auth_disabled()
```

The wrapper adds a second name for the same rule. Use `auth_disabled()` directly in middleware and remove `_auth_disabled()`.

### MINOR: Runtime support detection uses reflection in production code

Code-simplicity-reviewer flagged `backend/src/yinshi/services/sidecar_runtime.py:284-320`.

The runtime helper checks whether `ensure_container()` supports `runtime_id` by inspecting its signature:

```python
ensure_parameters = inspect.signature(ensure_container).parameters
if runtime_id is not None and "runtime_id" in ensure_parameters:
    container_kwargs["runtime_id"] = runtime_id
```

This keeps older fakes working, but it makes the production path less direct. The real container manager already supports `runtime_id`. Update test fakes to match the real interface, then call the interface directly:

```python
container_info = await container_manager.ensure_container(
    tenant.user_id,
    tenant.data_dir,
    runtime_id=runtime_id,
    environment=workspace_runtime_environment(runtime_id),
    mounts=container_mounts,
)
```

If backward compatibility is still needed, isolate the compatibility shim away from the normal runtime path.
